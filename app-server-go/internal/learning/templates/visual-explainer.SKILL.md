# 图文并茂与交互式图解制作手册（Visual Explainer）

好的技术导师懂得「一图胜千言」：复杂机制靠纯文字解释 800 字读者依然云里雾里，一张结构清晰的图或一个可点击演进的交互动画 15 秒就能让人彻底通透。

---

## 一、可视化载体选型矩阵（按概念类型选最趁手的工具）

| 知识类型 | 首选载体 | 展示方式 |
|---|---|---|
| 请求链路、系统架构、模块依赖、决策判断 | **Mermaid `flowchart LR / TD`** | 直接内嵌在回复 Markdown 中渲染 |
| 异步回调、跨进程/跨标签页通信、锁竞争、网络握手 | **Mermaid `sequenceDiagram`** | 直接内嵌在回复 Markdown 中渲染 |
| 生命周期、状态流转（任务/订单/连接/扫描状态） | **Mermaid `stateDiagram-v2`** | 直接内嵌在回复 Markdown 中渲染 |
| 数据库表关系、实体关联 | **Mermaid `erDiagram`** | 直接内嵌在回复 Markdown 中渲染 |
| **内存/二进制节区布局、盒模型、索引 B+Tree、时间轴对比** | **高清教学 SVG（`visuals/<project>/<slug>.svg`）** | 写文件后在 Markdown 用 `![图解说明](file:///绝对路径)` 直接展示！ |
| **多步骤动态机制（并发竞态、React 渲染撕裂、MVCC 可见性、构建产物对比、算法步进）** | **单文件交互式 HTML 教学模拟器（`visuals/<project>/<slug>.html`）** | 写文件后调用 `plugins.open` 在星序右侧 Sidecar 自动弹出交互！ |

## 二、Mermaid 专业制图铁律（零语法报错 + 清晰美观）

1. **特殊字符强制双引号**：节点标签内凡包含括号 `()`、方括号 `[]`、冒号 `:`、斜杠 `/`、引号或代码符号，**必须**用双引号包裹，例如：
   - ✅ `A["编译参数 (-s -w 剥离符号表)"] --> B["PE 节区熵值骤升"]`
   - ❌ `A[编译参数 (-s -w)] --> B[熵值升高]`（会触发解析失败！）
2. **严控信息密度**：单张 Mermaid 图节点数控制在 **5 ~ 12 个**，用 `subgraph` 做清晰分层或泳道，拒绝画成密密麻麻的蜘蛛网。
3. **语义化标签 + 双路径对比**：箭头上写明「触发条件/传递数据」，用虚线箭头 `-.->` 或明确标注区分「正常链路」与「踩坑/报错链路」。
4. **禁止在节点中塞入 HTML 标签**（如 `<br/>`、`<b>` 尽量少用或用简洁短句替代），确保桌面端与移动端都能优雅渲染。

## 三、高清教学 SVG 图解规范（结构/内存/布局类必杀技）

当 Mermaid 不足以表达**空间比例、内存块分布、二进制节区对比、指针指向或时间轴并行**时，直接手写一张干净的 SVG 图保存到 `visuals/<project>/<slug>.svg`：

- **画布与排版**：显式声明 `viewBox="0 0 880 420"`（留足边距 ≥ 28px，严禁文字贴边或溢出裁切）；
- **专业 Obsidian Slate 配色系统**（清晰高对比、克制高级，拒绝刺眼大红大绿）：
  - 画布底色：`#FAFAFC`，卡片填充：`#FFFFFF`，边框：`#E2E6EF`
  - 主文字：`#111318`，辅助说明：`#5A6272`
  - 核心机理高亮（靛蓝）：填充 `#EEF2FF` / 描边 `#4F46E5` / 字色 `#3730A3`
  - 警示/关键权衡（琥珀）：填充 `#FFFBEB` / 描边 `#D97706` / 字色 `#92400E`
  - 故障/踩坑高亮（绯红）：填充 `#FEF2F2` / 描边 `#DC2626` / 字色 `#991B1B`
- **字体栈**：统一使用 `font-family="-apple-system, BlinkMacSystemFont, 'PingFang SC', 'Microsoft YaHei', sans-serif"`，代码标注用 `'JetBrains Mono', ui-monospace, Consolas, monospace`。
- **内嵌展示**：生成后在对话回复里直接用标准 Markdown 嵌入，用户无需跳转即可看到完整高清图解：
  `![PE 节区结构对比图](file:///绝对路径/visuals/astrorder/pe-sections.svg)`

## 四、单文件交互式 HTML 动画图解规范（复杂机制终极武器）

当遇到**动态过程、状态竞态、多阶段流水线或「正常 vs 异常」对比**时，主动生成一个**零外部 CDN 依赖的单文件 HTML 教学页**，让用户亲自点按钮看懂底层演化！

### 必须具备的 4 项交互设计
1. **顶部标题 + 模式切换**：支持切换「✅ 正确机制」与「💥 踩坑/异常场景」对比观察；
2. **分步控制器**：提供 `上一步` / `下一步` / `自动演示` / `重置` 按钮与步骤进度条（通常 4~6 步）；
3. **动态可视化画布 + 同步高亮代码**：每切一步，SVG/DOM 图中的活跃节点、数据流箭头脉冲高亮，并同步高亮用户真实项目的对应代码行；
4. **底部人话旁白卡片**：每一步用 1~2 句通俗大白话解释「这一步到底发生了什么、为什么关键」。

### 生成后自动在星序 Sidecar 弹出
1. 将 HTML 保存至本工作区 `visuals/<project>/<topic-slug>.html`；
2. 写入参数文件（例如 `inbox/open-visual.json`）：
```json
{
  "plugin_id": "html",
  "path": "<交互式 HTML 的绝对路径>",
  "title": "互动图解：<主题简短名称>"
}
```
3. 调用星序原生 CLI 在右侧 Sidecar 自动打开：
```bash
astrorder-agent invoke plugins.open --input-file "<参数文件绝对路径>"
```
4. 同时在对话回复中给出「右侧已打开互动图解，建议先点『踩坑模式』再点『下一步』观察状态变化」的清晰操作引导（并保留 1 张精炼静态 Mermaid 图作为聊天记录内的永久速览，确保手机端看记录也能一眼明白！）。

## 五、排版呼吸感准则（写给人看，不写给机器看）
- **4 行法则**：任何纯文字段落不超过 4 行，及时拆成「加粗小标题 + 短句要点」；
- **对比必用表**：只要涉及「A vs B」「改动前 vs 改动后」「误区 vs 真相」，优先用 Markdown 表格一眼看穿；
- **代码必精简**：只贴最核心的 8~20 行真实代码并附人话注释，不把 200 行整文件直接倾倒在对话框里。
