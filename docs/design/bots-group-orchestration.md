# 群聊协作

群聊编排由 Go App Server 的 `internal/botgroups/` 维护，原生会话执行仍由 Session Daemon 托管。群聊可以在不同成员之间并行处理独立任务；每个成员各自维护待发送消息、执行状态和投递游标。

## 成员与会话

成员以独立 `member_id` 寻址，不能仅用 `agent_id` 区分。同一个 Agent 可以多次加入群聊，每次选择不同工作区、别名和角色。已有会话通过 fork 绑定到群成员，保留原有会话。

发送给成员的上下文包含其身份、群成员、接力轮次与待接收消息。黑板和跨服务器文件读取由星序能力入口提供，无需 Agent 自行实现产物转发协议。

## 发送时机

用户或成员的消息先写入群时间线。被提及且未禁言的成员进入待判断集合，System One 逐个决定立即发送还是等待依赖信息，同时判断当前请求是否完成。

例如用户要求先设计再开发，即使同时提及两人，也可以先投递设计。设计回复后再次判断，开发获得自上次投递以来尚未接收的群消息。忙碌成员不会被重复启动；不同空闲成员可以同时获得可执行的任务。

投递受理、执行完成和本轮结束是不同状态。受理后推进成员游标；最终回复与原生 command/turn 状态结合，决定结束、继续接力或进入错误状态。判断失败、缺少成员判断或结果不确定时显示错误，不能伪装为成功或已发送。

默认接力上限为 **10 次**，可设为 **1–20 次**。System One 和 Agent 均收到轮次信息；服务在实际发送前检查上限。超过上限的下一次接力保持未发送，用户可以调整设置后重新判断，或中断本轮。

## 禁言与恢复

点击成员切换禁言；“所有成员”批量切换。禁言成员不接收新任务，即使消息中提及它也不发送。禁言不强制终止已经受理的工作。

禁言与恢复时更新成员独立的跳过游标。恢复后不补发禁言期间的消息；需要共享这段讨论时，由用户或其他成员另发摘要。较早任务的延迟受理或失败不能回退这个边界。

## 黑板与产物

群黑板命名空间为 `group:<group_id>`，保留键 `artifacts` 由星序维护。产物保存首次发布者的来源身份、工作区和文件路径，后续同路径引用沿用该来源。

路径提及本身只构成文件引用。系统结合原生写入记录、文件可读性和交付语义核验产物；已有 skill、参考文件、日志与临时测试不因出现在回复中就自动成为产物。产物核验异步执行，不阻塞消息编排。

群内文件链接在对应群聊的 Sidecar 中打开，并携带实际来源。Agent 可通过群黑板和能力入口跨服务器读取产物内容。

## 维护入口

| 职责 | 位置 |
| --- | --- |
| 群、成员、消息与 HTTP 入口 | `app-server-go/internal/botgroups/groups.go` |
| 逐成员判断、游标与并行投递 | `coordination.go`、`decision.go` |
| 原生会话执行、fork 与恢复 | `native.go`、`fork_binding.go`、`recovery.go` |
| 禁言边界 | `member_mutes.go` |
| 原生证据与产物核验 | `artifacts.go`、`native_artifacts.go`、`artifact_decision.go` |
| 黑板产物结构与读取 | `app-server-go/internal/artifacts/`、`internal/blackboard/` |
| 桌面与移动群聊 | `frontend/src/features/chat/`、`frontend/src/features/mobile/MobileGroupsPage.tsx` |

除明确标明根目录的路径外，后端文件名均相对于 `app-server-go/internal/botgroups/`。实际字段、路由和状态转换以代码及对应测试为准。
