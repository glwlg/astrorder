# Electron 桌面端与大小内核管理开发方案

状态：初版代码已实现；登录启动任务与真实 Agent 会话的实机验收正在执行。目标平台为 Windows，安装包自带可运行的星序服务端。

开发运行：在 `desktop/` 执行 `npm install` 和 `npm start`。生成安装包执行 `npm run dist`，产物位于 `desktop/release/`。安装时只选择客户端安装位置，服务端随安装包写入该位置的 `server/`，不再要求选择已有源码目录。首次启动会在 `server/.runtime/` 生成本机配置和 DPAPI 加密凭证；使用状态页或托盘的“设置小内核登录启动”即可注册当前用户任务，无需 UAC 或 Windows 密码。

## 1. 目标与生命周期决策

用户打开客户端即可使用星序，通过托盘分别启动、重启、停止大小内核，无需手动运行脚本。

- **小内核 Session Daemon**：注册为当前用户的 Windows 登录启动任务。任务在用户登录后启动独立小内核；客户端启动时检查它，未运行则启动并等待就绪；关闭或退出客户端不停止它。
- **大内核 App Server**：随客户端启动；显式退出客户端时停止。关闭窗口只是隐藏到托盘，不停止大内核。
- **托盘**：分别展示大小内核的真实状态，各自提供启动、重启、停止及日志入口。
- **会话保护**：重启大内核不影响小内核。小内核停止或重启前检查权威会话状态；存在 `running`、`waiting_approval` 或无法可靠判断时，必须明确确认。

第一版包括登录启动任务注册与已有小内核复用、启动编排、托盘管理、本地服务状态页、退出清理和桌面打包。安装包携带后端、Python 环境、脚本、Codex connector 和前端产物；数据库、随机密钥和用户配置在首次启动时生成到 `%LOCALAPPDATA%/Astrorder`，升级时保留。托盘可直接复制访问令牌，不要求用户准备源码或日常操作脚本。

会话通知、全局快捷键和 Electron 自动更新不在本次范围。小内核与客户端在用户登录后自动启动属于本次范围。

| `scripts/restart_service.py` | 强制结束大内核单 PID 后启动，等待监听 | 提取独立动作，改为优雅停止，补就绪检测 |
| `scripts/start_silent.py` | 实际执行 restart | 保持入口兼容，不用于客户端自动启动，以免重启现有实例 |
| `scripts/status_daemon.py` | 仅监听元数据 | 登录任务状态与小内核权威状态分别查询 |
| `backend/src/astrorder/daemon/session_daemon.py` | 有 `status()`、运行时注册和 shutdown；现有 shutdown 未做活跃会话保护 | 复用运行内核，复用统一受保护停止入口 |

当前 `terminate_verified_pid()` 使用 `taskkill /F /PID`，并非优雅退出。大内核要随客户端日常退出，应先补可认证的本地退出控制，让 Uvicorn 执行正常关闭流程；不把强杀作为默认退出或自动兜底。

现有 `docs/production-deployment.md` 仍包含关闭连接器的旧更新说明。实现时同步改为大内核独立更新和小内核独立维护，并说明客户端退出会使其他浏览器暂时无法访问大内核。

## 3. 架构与所有权

```text
Windows 登录启动任务（当前用户，无密码）
  └─ 独立 Session Daemon → Codex / Hermes / SSH / PTY

Electron 主进程
  ├─ 托盘、窗口、状态页
  ├─ 本地管理命令 → 登录任务 / 小内核受保护管理接口
  └─ App Server（随客户端启停）→ 小内核认证 IPC

Electron 业务窗口 / 普通浏览器 → App Server HTTP / WebSocket
```

- 小内核是脱离 Electron 进程树的当前用户进程，由登录任务触发；Electron 退出不影响它。
- 大内核使用明确的生命周期控制；正常退出先停止大内核，再退出 Electron。大内核异常遗留时，下次启动验证归属后复用，不重复启动。
- Electron 异常崩溃后的大内核自动清理由存活管道实现：客户端与大内核维持本地管道，EOF 后大内核优雅退出。该管道与小内核无关，不使用进程树强杀。大内核如果自身卡死，客户端显示异常，不承诺它一定能及时退出。
- 启停编排位于 Electron 主进程及 Python 管理层，不依赖大内核在线，也不复制业务数据库或会话系统。
- 第一版管理一个已选定部署。对首次发现的、由脚本独立运行的大内核，先明确提示接管后将随客户端退出，并取得接管确认；未确认只允许查看，不终止它。接管关系绑定进程身份，不用一个永久开关接管未来未知进程。

其他客户端已持有会话时，小内核按宿主能力继续控制：Hermes 通过已加载插件的 `ctx.inject_message()` 原地提交；Codex Desktop 在已验证的回环 CDP 实例中按任务 ID 定位侧栏任务、切换到目标任务并提交文本。CDP 只接受 Dream Skin 状态记录的浏览器实例，目标任务必须在唯一窗口的侧栏 DOM 中出现；纯 Codex CLI、附件、归档或尚未加载的任务不走该路径，仍保留原生 active-writer 拒绝。

## 4. Windows 登录启动任务

### 4.1 托管方式

客户端通过 Windows Task Scheduler COM API 为当前用户注册 `AstrorderSessionDaemon` 登录触发任务，使用 `TASK_LOGON_INTERACTIVE_TOKEN` 和普通用户权限。任务动作使用安装目录内的无窗口 Python 解释器与绝对脚本路径，加载 DPAPI 配置后启动独立小内核并退出。大小内核都以无控制台窗口方式运行，无需管理员权限、Windows 密码或 Session 0 服务环境。

登录任务只负责登录时触发。托盘中的启动操作直接复用同一独立进程入口；停止与重启仍通过小内核认证 IPC 和会话守卫执行，不调用任务管理器强制结束进程。

### 4.2 生命周期边界

- 用户登录后任务启动小内核；Electron 同时启动时会核验并复用同一实例。
- 关闭或退出 Electron 不停止小内核。
- 用户注销或 Windows 关机会结束当前用户进程；下次登录重新启动。
- Codex/Hermes 登录状态、SSH 配置、DPAPI 凭证和映射盘都使用当前交互用户环境。
- 安装目录迁移或升级后重新注册任务，确保动作路径指向当前安装目录。
- 登录任务启动失败不创建第二种托管方式；客户端展示实际错误并允许从托盘重试。

### 4.3 已有小内核

发现端口已有经身份与认证核验的星序小内核时直接复用，并注册登录任务；端口冲突、状态不完整或身份不符时明确报错，不终止未知进程。

## 5. 客户端生命周期

### 5.1 打开客户端

1. 获取单实例锁，第二次启动只唤起窗口。
2. 校验安装目录内置的 `server/`，首次启动生成本机配置与加密凭证；文件缺失或初始化失败时显示错误并退出，不留下无窗口主进程。
3. 查询登录任务与小内核认证状态。已就绪则复用；确认停止则启动并等待就绪；异常、冲突或未知则显示具体错误，不自动重启。
4. 小内核就绪后启动大内核；已属于客户端管理的健康实例可复用。生产入口核验并复用独立小内核。
5. 大内核健康、与小内核连接就绪后加载业务页。登录仍使用现有认证流程。

首次安装后，正常使用无需再点击“启动”；小内核即使登录时未成功启动，客户端也会尝试一次启动并展示结果。

### 5.2 关闭与退出

| 用户动作 | 大内核 | 小内核 |
| --- | --- | --- |
| 关闭窗口 | 保持运行，窗口隐藏到托盘 | 保持运行 |
| 托盘“退出星序” | 优雅停止客户端管理的大内核，再退出 Electron | 保持运行与托管会话 |
| 客户端异常退出 | 存活管道断开后请求优雅退出；卡死实例需后续处理 | 不受影响 |
| 再次打开客户端 | 自动启动或验证复用 | 检查并确保启动，不隐式重启 |

正常退出若大内核停止失败，保留托盘并展示错误，允许重试；不自动升级为强杀，也不声称已经退出。停止大内核期间，小内核仍执行任务，但其他浏览器暂时不能访问星序、处理审批或接收业务事件。

客户端保持打开时，用户在托盘主动停止某个内核后，状态轮询只展示状态，不自动重新拉起，避免与用户操作对抗。下次启动客户端重新执行正常启动编排。

## 6. 托盘菜单与依赖关系

菜单结构：

```text
打开星序
大内核：运行中
  启动大内核
  重启大内核
  停止大内核
  查看日志
小内核：运行中
  启动小内核
  重启小内核
  停止小内核
  查看日志
退出星序
```

每个内核独立显示：未安装、已停止、启动中、运行中、停止中、重启中、异常、状态未知。未安装仅适用于小内核。跨内核操作串行，操作期间禁用冲突动作，保留打开窗口与日志能力。

| 操作 | 执行规则 |
| --- | --- |
| 启动大内核 | 先确保小内核启动并就绪，再启动大内核 |
| 重启大内核 | 只停止、启动大内核；小内核不可用时报告依赖异常，不隐式重启小内核 |
| 停止大内核 | 仅停止大内核，保留托盘和小内核 |
| 启动小内核 | 仅启动独立进程；如果大内核原本运行则允许恢复连接，不擅自启动已被用户停止的大内核 |
| 重启小内核 | 完成会话保护后重启服务；原本运行的大内核保持进程存活，暂停新调度，随后重新认证连接 |
| 停止小内核 | 完成会话保护后停止服务；大内核保持运行但会话执行不可用，明确显示离线状态 |

小内核离线时大内核不能另起小内核，也不能继续投递新指令。小内核重启改变实例身份，前端／大内核必须重建订阅与真实状态；不能沿用旧 WAL 游标宣称执行恢复，更不能自动重发未确认的指令。

## 7. 小内核停止与重启保护

该保护必须在服务／小内核侧统一实现，不能只存在于 Electron 弹窗。现有 `daemon.shutdown`、`stop_daemon.py`、服务管理命令都必须路由到同一检查，不得保留可绕过的应用入口。

流程：

1. 通过认证管理通道获取当前小内核实例和完整权威状态，依据现有 `SessionDaemon.status()` 核对托管会话，并校验运行时注册与快照覆盖是否完整。
2. 在小内核侧以同一互斥边界检查会话并进入维护状态，阻止新建、恢复、提交轮次及其他可产生运行任务的入口。仅 UI 禁用按钮不足以防止竞态。
3. 明确没有 `running`、`waiting_approval` 且状态完整时，可执行停止或重启。
4. 有活跃会话时，返回受影响会话与待审批数量，客户端展示明确动作，例如“重启小内核将中断 2 个运行中的会话和 1 个待审批会话。”按钮为“取消”和“中断会话并重启”。用户取消后解除维护状态。
5. 状态不可读取、不完整或有歧义时，按存在活跃会话处理，提示“无法确认会话状态，停止小内核可能中断正在执行的任务”，必须明确确认。超时、等待或关闭弹窗均不构成确认。
6. 确认绑定当前服务实例、操作和一次性短期凭据，不持久化“以后不再提醒”。实例变化、凭据过期或操作改变时重新检查；断开或取消释放维护状态。
7. 获准后关闭托管运行时，等待小内核报告停止；重启随后启动独立进程并完成认证就绪检查。失败如实展示，不自动强杀。

受保护管理使用小内核现有的认证回环 WebSocket：状态查询返回权威会话状态，shutdown 在小内核内部执行同一守卫，不能仅有共享 secret 就跳过检查。登录任务只负责启动；所有应用内停止操作都走受保护的 shutdown。

如果小内核认证 IPC 故障，客户端报告状态未知并拒绝常规停止；不因用户确认了会话中断，就擅自把正常停止改成进程树强杀。管理员通过系统工具强制终止属于平台边界。

任务管理器强制终止和系统注销／关机属于平台边界，不能声称可被此机制阻止。

## 8. 统一管理与错误处理

Python 管理层接收固定 `target=app|daemon` 与 `action=status|start|stop|restart`，服务安装／修复走单独受限提权入口。旧脚本调用同一实现，避免两套启停行为。

命令使用解释器绝对路径及参数数组，固定 cwd、隐藏控制台，不拼接 shell。stdout 返回单个结构化 JSON；stderr 和日志保留脱敏诊断。结果至少包含目标、动作、成功标志、实际状态、经核验的实例身份及失败原因；需要确认时返回明确状态而非执行操作。

- 同一部署使用跨进程操作锁，避免桌面端、旧脚本、服务安装并发。维护锁位于小内核，负责阻止会话进入；两者作用不同。
- 端口来自现有生产配置，当前默认大内核 30001、小内核 30009，不在 Electron 重复写端口策略。
- 大内核身份核验结合解释器绝对路径、部署入口、启动身份与端口；停止前再校验。旧命令行只含相对路径时，不能仅凭相同文件名接管。
- `current_listening_pids()` 必须区分命令失败与空监听；现有 WMIC 查询需替换为目标 Windows 可用的统一查询方式，失败显示未知。
- 小内核身份结合监听 PID、命令行和认证 IPC 实例信息核验；端口监听和元数据文件不足以证明服务归属或会话空闲。
- HTTP `/health` 只用于大内核健康，另验证其小内核连接。登录任务存在与小内核认证就绪分别展示，不把端口占用当就绪。
- 建议启动预算 30 秒、正常停止预算 10 秒；超时返回最新实际状态，不自动重复操作。
- 大内核启动失败不停止已经运行的小内核；小内核重启失败不启动普通 detached 副本兜底。
- 日志沿用 `.runtime/production.log`、`.runtime/session-daemon.log`；登录任务启动失败提供明确错误。不存在日志时明确提示。

## 9. 前端与本机权限边界

业务页继续加载已验证本机 origin，使用原有 HttpOnly Cookie 登录，不解密或注入生产秘密。Renderer 启用沙箱与上下文隔离，不开放 Node 能力。

preload 只向受信任本地状态页开放固定管理动作；主进程校验来源、主框架和参数。Sidecar、工件 iframe、第三方页面不能获得启停能力。外部 HTTP／HTTPS 链接使用默认浏览器，不能为了预览关闭全局 Web 安全检查。

登录任务不需要 Windows 密码。星序 IPC 密钥由 Python 读取 DPAPI 配置，新生成的管理凭据使用安全随机值并限制访问，不进入 Renderer。

窗口关闭隐藏到托盘，单实例运行；窗口恢复时校验显示器边界。本地状态页独立文件，分别展示大小内核与可执行动作，小内核不可用时仍能管理。产品文案例如“正在启动小内核”“小内核已停止，启动后可继续操作会话”，不放实现说明。

## 10. 建议文件组织与实施顺序

```text
desktop/
  package.json
  main.js                      托盘、窗口、单实例、管理命令与退出编排
  preload.js                   受限桥接
  service-status.html          独立服务状态页
  service-status.js            状态页交互
scripts/
  app_service.py               大内核统一生命周期
  start_desktop_daemon.py      登录任务启动入口
  production_config.py         提取现有配置与 DPAPI 加载
  service_lifecycle.py          复用、补强身份判断
```

小内核会话守卫放回现有 daemon 模块，所有调用者共享；具体文件数量按实现需要调整，不为安装、托盘和 CLI 各建一套业务层。桌面依赖独立于网页包；安装包携带服务端程序，但不携带数据库、运行凭证和用户配置。

实施阶段：

1. **登录任务验证**：验证当前用户登录触发、DPAPI、路径、Codex/Hermes/ConPTY/SSH 与退出 Electron 后持续运行。
2. **生命周期与保护**：统一配置和服务动作，完成小内核原子维护守卫、登录任务注册／迁移、大内核优雅退出及客户端存活管道。
3. **桌面闭环**：首次安装界面、自动启动顺序、双内核托盘、明确确认、异常反馈、退出编排与日志。
4. **Windows 包与回归**：标准用户运行、提权安装、重启系统后的服务启动、旧脚本兼容、实际会话存活验证和部署说明更新。

## 11. 验收清单

复用现有 pytest 测试体系覆盖管理与守卫逻辑；浏览器页面调试优先内置浏览器，登录任务、托盘和进程生命周期必须在真实 Windows / Electron 中验证。

| 场景 | 通过标准 |
| --- | --- |
| 大小内核都停止后打开客户端 | 自动先启动小内核再启动大内核，进入可用业务页 |
| 用户登录后未打开客户端 | 登录任务自行启动小内核，当前用户配置有效 |
| 首次设置登录启动 | 无需提权或密码，任务注册后启动小内核 |
| 旧小内核迁移且有活跃会话 | 必须明确确认，取消后旧进程与任务保持 |
| 当前用户登录环境 | DPAPI、Agent 登录、SSH、PTY 和真实工作区操作成功 |
| 双击客户端或连续点击菜单 | 一个客户端、每种内核一个实例，没有并发启停 |
| 关闭窗口 | 托盘、大小内核均继续运行 |
| 显式退出客户端 | 大内核正常关闭，小内核 PID 和托管会话保持 |
| 客户端异常终止 | 小内核不受影响；健康大内核检测 EOF 后正常退出 |
| 大内核退出失败 | 保留错误状态、不假报成功、不自动强杀 |
| 重启／停止大内核 | 小内核及托管任务保持；重开后状态恢复，不重复调度 |
| 停止小内核，无活跃会话 | 服务正确停止，大内核显示离线，不自动派生小内核 |
| 停止／重启小内核，有 running 或 waiting_approval | 明确提示受影响会话；取消无中断；确认后才执行 |
| 权威状态不可读或不完整 | 必须确认；管理通道也失效时明确失败，不自动强杀 |
| 检查期间新任务进入 | 维护锁阻止进入或使检查失效，不能绕过确认 |
| 确认过期、实例替换、重复提交 | 旧确认不能用于新实例或另一次操作 |
| CLI、WebSocket shutdown、托盘控制 | 应用内所有停止路径遵循同一会话守卫 |
| 小内核重启后大内核仍运行 | 重建连接与状态，旧游标／未确认命令不会导致假恢复或重发 |
| 用户手动停止后状态轮询 | 不自动拉起；下次客户端启动才执行正常启动策略 |
| 端口被他人占用、系统查询失败 | 明确冲突或未知，不误杀、不创建重复进程 |
| 有数据库写入时退出大内核 | 正常关闭、数据库一致，未确认请求不自动重发 |
| 登录任务失败、凭证失效、盘符不可见 | 显示具体错误及修复入口，不切换账户或启动机制兜底 |
| 桌面端升级 | 小内核进程保持；不覆盖运行中小内核依赖文件 |
| 第三方 iframe / 工件页面 | 无法调用服务管理或读取凭证 |

本文同时记录初版实现与后续验收目标。后续真实小内核停止／重启仍遵守根目录 `AGENTS.md` 的会话保护约束。
