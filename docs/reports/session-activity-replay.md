# 最近活跃时间被重启时间刷新

用户报告：重启后，多条无新活动的 Codex 会话显示与重启时间相同的最近活跃时间。截图提供了现象；本轮未读取生产数据库、聊天或凭据，也未逐条取得截图会话的事件证据。

已复现的代码缺陷：

- 大内核 WAL 投影中，Codex turn start/completion/approval 及共用状态投影以 `datetime('now')` 写入 `sessions.updated_at`。补处理历史事件时使用的是处理时间。
- runtime owner/loss 与只读状态同步也会改变最近活跃时间。
- 原生活动对账只向前推进，不能自动修复已经过大的时间值。

修复：

- 在事件投影事务中绑定 `EventEnvelope.timestamp_unix_micros`，状态事件使用原事件时间并只向前推进；缺失原时间戳时保留已有活动时间。
- owner 登记／丢失及只读状态同步保留活动时间，继续更新状态或进程信息和发布事件。
- 修复位于大内核。没有替换已安装程序、重启服务或回写现有会话时间。

验证：

- 测试先复现历史 Codex 事件被写为当前时间，修复后保留原时间、微秒精度、单调性与缺失时间戳行为。
- owner 登记、状态同步和共用状态／生命周期测试均先失败后通过。
- projection/store/sessions 三包 221 项测试通过；对应 go vet 和大内核构建通过。
- 独立源码片段审查通过，未报告安全或逻辑错误。首次读取式审查被 Windows DPAPI 沙箱错误阻断，改为输入相关源码片段、禁止审查工具调用；审查范围仅为本轮时间处理改动。
- 全量 App 测试：980 passed、13 failed、8 skipped。失败位于生命周期／安装前提（含 Hermes stdio gateway unavailable、App 子进程启动）及音频进程生命周期／临时文件清理，未证明为本轮引入或既有。首轮全量命令 60 秒超时，后续完整运行失败结果保留。
