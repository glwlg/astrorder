# 扫码登录

电脑网页的登录页提供扫码登录和访问令牌登录。已登录的手机在工作台菜单中选择“扫码登录电脑”，扫描电脑二维码；也可以使用手机相机打开扫码链接。手机核对确认码和浏览器名称后点击确认，电脑自动建立登录会话。

电脑和手机需要使用同一星序地址，且手机当前浏览器在该地址已登录。localhost / 127.0.0.1 不能被另一部手机直接访问；应使用局域网地址或域名。外部相机打开的浏览器与已登录 PWA 不一定共享 Cookie，可在已登录的星序内扫描。局域网 HTTP 页面无法调用摄像头时，可上传二维码图片识别。

二维码包含随机请求 ID 和独立的扫码密钥，放在 URL fragment 中，不包含永久访问令牌。请求有效期三分钟，保存在大内核内存中；大内核重启后需要刷新二维码。手机只有在既有 Cookie/Bearer 登录态验证通过且用户确认后才能授权，扫码链接的 query token 不参与手机认证。PC 的 HttpOnly 绑定 Cookie 与二维码密钥分离，只有发起请求的浏览器能领取会话，成功后原子删除请求，防止重复领取。刷新二维码会退役旧请求。

API 均为 POST，要求显式且允许的 Origin，响应设置 Cache-Control: no-store：

| 路径 | 身份与用途 |
| --- | --- |
| `/api/v1/auth/qr/create` | 未登录 PC 创建请求并接收绑定 Cookie |
| `/api/v1/auth/qr/poll` | 原 PC 轮询；批准后一次领取登录 Cookie |
| `/api/v1/auth/qr/inspect` | 已登录手机读取状态、确认码和浏览器名称 |
| `/api/v1/auth/qr/approve` | 已登录手机明确批准或拒绝 |

服务端限制每个直连来源最多 20 个未过期请求、总计最多 1024 个，超限返回 429。反向代理不信任任意转发 IP；共享代理可能共享来源限额。

验证覆盖服务端请求绑定、过期、刷新、拒绝、并发单次领取及独立 HTTP Cookie 容器。真实 Chrome 使用独立 PC、手机及第三方浏览器上下文，读取实际生成的二维码图片，验证未登录手机被拦截、手动批准后仅原 PC 获得会话、拒绝后 PC 保持未登录以及领取后重放返回 410。摄像头路径使用 Canvas.captureStream 提供真实视频帧，扫码后核对所有轨道已停止；尚未使用实体手机相机实拍。

2026-10-17 已发布网页及大内核，合并保留当前已交付功能。最终候选通过后端 1130 项测试（10 项跳过）、前端 642 项测试，以及 vet、lint、类型检查和构建。在安装版实际 HTTP 服务上，真实 Chrome 读取二维码图片，完成已登录手机明确授权、原 PC 获得会话和第三方浏览器保持未登录。113 个网页文件及大内核哈希读回一致；小内核及其 25 个直接子进程身份保持不变。源码尚未提交推送。
